# EventLoop

Подбор мероприятий по Пушкинской карте в формате свайпов.

Работа поделена надвое. **Бот в MAX** спрашивает одно — сколько всего на карте
и сколько из этого на кино — и присылает кнопку, которая открывает мини-приложение
и передаёт ему оба кошелька.
**Мини-приложение** делает всё остальное: карточки, свайпы, фильтры по дате,
категории и расстоянию, избранное, подтверждение покупки и подсчёт остатка.

Листать карточки в переписке медленнее, а две реализации одной ленты расходятся
на второй же правке — поэтому лента живёт только в приложении.

## Бот

**https://max.ru/t560_hakaton_max_bot** — «Хакатон МАХ 560», `@t560_hakaton_max_bot`

Имя и ссылку приложение печатает в лог при каждом старте:

```
Связь с MAX есть. Бот: «Хакатон МАХ 560», username: @t560_hakaton_max_bot, id: 387017712
Открыть диалог: https://max.ru/t560_hakaton_max_bot
```

Если вместо этого в логе ошибка — токен отозван или недействителен.

## Запуск

Нужен только Docker. Java, Maven и PostgreSQL ставить не надо — всё собирается
внутри образа.

```bash
docker compose up --build
```

Токен бота лежит в `.env` рядом с `compose.yaml` и подхватывается автоматически,
поэтому команда одна. Если `.env` потерялся, compose остановится с подсказкой,
а не поднимет молча неработающего бота: скопируйте `.env.example` в `.env`
и впишите `MAX_BOT_TOKEN`.

Первая сборка занимает несколько минут — Maven тянет зависимости. Одна команда
поднимает приложение и PostgreSQL. Схема, площадки, станции метро и афиша
из 163 мероприятий приезжают миграциями Flyway при старте: отдельных шагов нет,
интернет для наполнения базы не нужен.

Остановить: `docker compose down`. Стереть и данные: `docker compose down -v`.

## Проверка основного сценария

Порядок шагов и что должно получиться на каждом.

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1 | `docker compose up --build` | В логе `Started EventLoopApplication`, затем `Связь с MAX есть. Бот: «Хакатон МАХ 560»` |
| 2 | `curl http://localhost:8080/actuator/health` | `{"status":"UP"}` |
| 3 | Открыть https://max.ru/t560_hakaton_max_bot и нажать «Начать» | Бот здоровается и спрашивает, сколько всего на карте |
| 4 | Отправить `5000` | Бот принимает сумму и спрашивает, сколько из неё на кино: «Напиши сумму до 2000 ₽, остальное посчитаю сам.» |
| 5 | Отправить `2000` | Бот пишет, что дальше всё делается в мини-приложении, и присылает кнопку «🎭 Открыть подборку» |
| 6 | Отправить вместо суммы `абв` или `-5` | Бот отвечает, что не понял, и остаётся на том же шаге — диалог не ломается |
| 7 | Нажать кнопку | Внутри MAX открывается мини-приложение, экран «Карта событий уже ждёт тебя»; в профиле кошельки 2000 и 3000 ₽ |
| 8 | Свайпнуть вправо | Открывается подборка: фильтры, счётчик `1/50`, карточка мероприятия |
| 9 | Свайпать карточки влево и вправо | Счётчик растёт, карточки меняются, кнопка возврата слева от счётчика отменяет последнюю оценку |
| 10 | Открыть «Избранное» | Во вкладке «Пойду» лежат лайкнутые, во вкладке «Отложенные» — отложенные |
| 11 | Открыть карточку из избранного и нажать «Купить билет» | Открывается страница мероприятия у билетного оператора |
| 12 | Открыть «Профиль», нажать карандаш у кошелька, ввести сумму | Остаток и полоса пересчитываются; уже подтверждённые покупки повторно не вычитаются |
| 13 | Перезагрузить приложение | Избранное, фильтры и баланс на месте — состояние переживает перезагрузку |

Проверено вручную с телефона: сценарий проходится целиком, бот отвечает,
приложение открывается по кнопке из диалога, свайпы, избранное, фильтры,
редактирование баланса и переход к покупке работают.

### Требования

Только Docker. Java и Maven локально не нужны — сборка идёт внутри образа.
Для запуска без контейнера понадобится **JDK 21** и PostgreSQL 17.

### Токен

Токен берётся **только** из переменной окружения `MAX_BOT_TOKEN`, в исходном коде
его нет. `.env` в `.gitignore`, в git и в образ не попадает — в поставку решения
кладётся отдельным файлом.

Получить токен можно в личном кабинете MAX для партнёров. Учтите два
организационных ограничения: бот создаётся только при верифицированном профиле
организации, ИП или самозанятого, а пользователи получают к нему доступ
**после прохождения модерации** — это срок, который стоит заложить заранее.

## Что внутри

| Слой | Где | Роль |
|---|---|---|
| Транспорт MAX (long polling) | `gateway/MaxGateway` | Единственное место с типами SDK |
| Диалог бота | `dialog/DialogRouter`, `dialog/Screens` | Состояния, тексты, кнопка мини-приложения |
| Разбор суммы из свободного текста | `dialog/BalanceParser` | «2 тыс», «2000р», «2000 рублей» → число |
| Лента, фильтры, избранное, кошельки | `src/main/resources/static/app` | Mini App, чистый JS без сборки |
| Импорт афиши | `importer/` | Разбор страниц оператора, сопоставление площадок |
| Расстояние между точками | `geo/Haversine` | Используется импортом и планируемым серверным фильтром |
| Схема, справочники, афиша | `src/main/resources/db/migration` | Flyway |

Стек: Java 21, Spring Boot 4.1.1, PostgreSQL 17, Flyway 12.4.0,
`ru.etsft.max:max-bot-api-spring-boot:0.5.0`. Версии зафиксированы в `pom.xml`
точными значениями или родительским BOM, диапазонов нет.

### Как компоненты связаны

```
MAX ──long polling──> MaxGateway ──> DialogRouter ──> PostgreSQL (состояние диалога)
                                          │
                                          └──кнопка с балансом──> Mini App (GitHub Pages)
                                                                        │
                                                                        └──> билетный оператор
```

**Бот и приложение связаны ровно одним контрактом** — параметром запуска.
Бот присылает кнопку `open_app`, которая открывает мини-приложение бота внутри
MAX, и кладёт в её `payload` оба кошелька: `2000_3000` (кино_остальное; MAX
пропускает в payload только латиницу, цифры, `_` и `-`). Приложение получает
его через мост MAX в `WebApp.initDataUnsafe.start_param`, читает суммы как
остаток на текущий момент и проверяет как чужой ввод: нечисловое, отрицательное
или больше номинала кошелька значение игнорируется. Прямая ссылка
`?cinema=2000&other=3000` тоже понимается.

Кнопке нужен username бота — переменная `MAX_BOT_USERNAME`; не задана — бот
отвечает текстом без кнопки и пишет об этом в лог, а не молчит. Адрес самого
приложения (GitHub Pages) привязан к боту в @MasterBot. Кнопка мини-приложения
в меню бота открывает его без суммы — тогда приложение считает от номинала.

### Решения, которые стоит знать до правок

**Бот спрашивает только баланс:** сначала сколько всего на карте, потом сколько
из этого на кино. Остальное — разница, и она должна влезть в свой кошелёк:
при 5000 ₽ на карте на кино может быть только 2000 ₽. Всё остальное — в приложении. Команда одна,
`/start`; меню, фильтры и кнопки под карточками из бота убраны.

**Состояние диалога — в PostgreSQL.** Строка в `app_user` создаётся при первом
сообщении, поэтому перезапуск контейнера не сбрасывает разговор на середине.

**Состояние ленты — в `localStorage` браузера.** Лайки, отложенное, покупки
и фильтры не уходят на сервер. Следствие в разделе «Ограничения».

**Схема описывает только то, что работает.** Таблицы под серверные реакции
и покупки убраны миграцией `V6`: пустые таблицы обещали синхронизацию, которой
в MVP нет. Вернуть их — значит вернуть и код, который в них пишет.

## Тесты

```bash
./mvnw test
```

106 тестов, все проходят. Заметная часть проверяет **сами данные**, а не код:
координаты площадок, наличие файла афиши у каждой карточки, уникальность
идентификаторов, цену в пределах кошелька и то, что ссылка ведёт на страницу
мероприятия, а не на поиск. Опечатка в пути к афише не падает исключением — она
даёт пустой прямоугольник, который заметишь, только долистав до него.

Живая проверка ссылок требует сети и вынесена под флаг — прогоняйте перед показом:

```bash
./mvnw test -Dlinkcheck=true -Dtest=SeedLinkCheckTest
```

## Данные

Два набора, и это важно понимать до показа.

**База.** `R__seed_z_events.sql` — 163 мероприятия, снятые импортом со страниц
Пушкинской карты билетного оператора ticketland.ru: настоящие названия, даты,
цены, ссылки и афиши. Площадки, адреса и координаты настоящие (координаты
приблизительные, ±150 м). Станции метро — 347 штук из OpenStreetMap.
Сид зафиксирован в миграции, чтобы `docker compose up` давал работающее демо
без сети: у источника антибот-защита, и на чужой машине запрос может не пройти.
Свежую афишу подтягивает `POST /admin/import` — он обновит те же строки
по `external_key`.

**Mini App.** `static/app/data.js` — 57 мероприятий и 58 локальных афиш.
Отдельный набор, потому что приложение не обращается к серверу (см. «Ограничения»).
Афиши скачаны со страниц оператора, права принадлежат организаторам,
подробности и ссылки на оригиналы — в `static/app/assets/events/CREDITS.md`.
Перед публичным запуском их нужно либо отдавать по ссылке на лету, либо
согласовать с правообладателями.

## Ограничения

Что осознанно не сделано в MVP:

- **Лента работает на собственном датасете приложения, а не на базе.** Mini App
  не ходит на сервер: 57 мероприятий зашиты в `data.js`. База хранит состояние
  диалога бота и служит приёмником импорта. Связать их — отдельная работа:
  нужен эндпоинт ленты, фильтры на сервере и синхронизация реакций.
- **Лайки, отложенное и покупки живут в браузере.** Другое устройство их
  не увидит, очистка данных сайта стирает. Серверной синхронизации нет.
- **Фильтр по расстоянию считает от центра Москвы**, а не от реального
  положения пользователя: геолокацию приложение не запрашивает.
- **Даты сеансов — с 30 сентября по 31 декабря 2026.** Прошедшие лента скрывает,
  так что после этого срока датасет нужно обновить импортом.
- **Только Москва.** Площадки и метро — московские, проверка координат в схеме
  это закрепляет.
- **Диалог бота ведётся на русском** и не локализован.
- **Импорт закрыт токеном и запускается руками.** Расписания нет.

## Переключение на webhook

Long polling выбран, чтобы демо поднималось на ноутбуке без публичного адреса.
Для production переключение — смена `MAX_BOT_MODE` на `webhook` и заполнение
`MAX_WEBHOOK_URL` и `MAX_WEBHOOK_SECRET`. Требуется HTTPS на 443 и сертификат
доверенного УЦ, самоподписанные MAX не принимает. Код `DialogRouter`
при этом не меняется.
